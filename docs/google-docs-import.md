# Importing existing records (Google Docs and local files)

Spec §11.3. Hugh's practice records are scattered across Google Docs and local files. There are two routes into **one importer** (`GrimoireCore/Import`), and both land items in the **Inbox** for confirm-and-correct. Nothing is filed silently, and the app itself never calls a Google API.

## Route 1: local files

Download a Doc (File → Download → **.docx**, **.md** or **.txt**), or export a whole Drive with Google Takeout (Docs arrive as .docx), and import the files or the folder:

```bash
grimoire import ~/Downloads/Takeout --tz America/Los_Angeles --lat 37.77 --lon -122.42 --dry-run
grimoire import ~/Downloads/Takeout --tz America/Los_Angeles --lat 37.77 --lon -122.42 --attachments ~/Grimoire/attachments
grimoire inbox
```

Folders are walked recursively; hidden files, Word lock files (`~$…`) and other extensions are skipped. Options go after the paths. `--dry-run` shows how each file would split without saving anything. In the Mac app the same code runs on files dropped onto the window or into `Imports/`.

## Route 2: Google Docs connector

Claude, with the Google Drive/Docs connector, reads the chosen Docs and writes each one as a Markdown file into an import folder, then runs `grimoire import` on that folder. The file is the Doc's text as Markdown (headings as `#`, lists as `- `), with this frontmatter:

```markdown
---
source: google-docs
google_doc_id: 1AbCdEfGhIjKlMnOpQrStUvWxYz0123456789
source_url: https://docs.google.com/document/d/1AbCdEfGhIjKlMnOpQrStUvWxYz0123456789/edit
title: Magical diary autumn 2025
modified: 2025-11-02T09:00:00Z
tags: [source/google-docs]
---
# Magical diary autumn 2025

## 3 October 2025 — Ritual: opening the directions
…
```

Every key is optional. `title`, `source_url` and `google_doc_id` are kept as provenance on each entry (its *Extra notes*, and the Inbox source `import:gdoc:<id>`). `tags` go on every entry. `modified` is the date used if the text has no dates. A single undated note may also set `type` (journal, ritual, meditation, vision, contact, omen, insight, dream, divination), `date` and `time_zone`.

Claude should not split, retype or summarise the Doc: the importer does the splitting so both routes give the same result. Fixture pair: `Tests/GrimoireCoreTests/Fixtures/import/` (generated by `tools/make_import_fixtures.py`).

## How a document becomes entries

- **Splitting.** A dated heading or a line that starts with a date begins a new entry. If the document has any dated headings, only headings split it, so a date at the start of a line of prose stays in its entry. Text before the first date is dropped if it is only the document title, and kept as its own entry otherwise.
- **Dates.** `2025-10-03`, `3 October 2025`, `3rd of Oct 2025`, `Saturday, October 4, 2025`, `10/04/2025` (month first unless `--dmy`; a date that reads both ways gets a note), optionally followed by a time (`21:40`, `9:40 pm`, `20h15`, `at 9pm`). Without a time the entry is set to noon in the import zone and its planetary hour is left blank. A document with no dates at all becomes one entry dated by its `modified` frontmatter, the .docx's own modified date, or the file's modification time, with a note.
- **Title and type.** Whatever follows the date on the line is the title (up to 80 characters; longer text starts the body). A type word in the title sets the type (dream, omen, contact, vision/pathworking, meditation, ritual/rite/LBRP, reading/tarot/Yi Jing, insight, journal). Otherwise a found reading makes it a divination, otherwise journal, with a note to check.
- **Readings.** The body goes through the same parser as voice captures, so `Deck Rider-Waite. Three card. Three of cups reversed, the Tower, page of wands.` and `Yi Jing, coins. 7 8 9 6 7 7.` become draft draws and casts. Divinations that name no card and no line values are dropped, so a passing mention of the I Ching doesn't create one. Confirm turns a draft into an Inquiry as usual.
- **Tags.** Frontmatter tags, `--tag` values and inline `#entity/crow` style hashtags.
- **Provenance.** The original file is copied to `imports/<hash>-<name>` under the attachments folder and attached to every entry from it.
- **Duplicates.** Each entry gets an import id from its date and words (`import-<hash>`, stored in `captureId`). Importing a file again, or the same Doc by the other route, is a no-op. Formatting differences between the .docx and the Markdown don't change the id.

After confirm, `grimoire export` writes the entries to the Obsidian vault as Markdown with YAML frontmatter (spec §11.1).

## Limits

- .docx: text, headings, lists, tables (as `a | b` rows), tabs and line breaks. Images, comments, footnotes and tracked deletions are ignored. Zip64 and encrypted files are refused.
- Photos of physical notes are not imported here; they go through Volumes (spec §7).
